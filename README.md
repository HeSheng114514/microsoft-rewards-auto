# Microsoft Rewards 自动签到

一个在 Windows 上常驻运行的桌面工具：**软件打开后按你设定的时刻，自动为每个账号完成 Microsoft Rewards 的每日搜索与任务**。支持**多账号**，每个账号使用完全独立的浏览器配置与登录态。提供本地网页控制台查看状态、改设置、看日志；关闭控制台页面后程序继续在**系统托盘**后台按计划执行。

> 本项目仅供个人学习与自动化技术研究使用。请先阅读文末的[使用须知](#使用须知)。

---

## 功能

| 功能 | 说明 |
| --- | --- |
| **多账号支持** | 每个账号独立的登录态（浏览器配置目录）、独立的运行历史与统计 |
| **定时自动执行** | 每天固定时刻（可多个）或每隔 N 分钟，**依次为所有启用账号**执行 |
| **多账号错峰** | 账号之间自动间隔启动（默认 90 秒），避免同时开多个浏览器 |
| **错过自动补跑** | 电脑关机/休眠错过计划时刻，开机后自动补上 |
| **自动搜索刷积分** | 模拟真人节奏搜索，**刷到积分不再增长为止**（不会白刷） |
| **可切换移动端搜索** | 按账号开启「移动端模式」，用手机 UA 覆盖移动端搜索额度 |
| **每日活动任务** | 自动完成「每日活动」里的搜索类任务（点击卡片，确保积分归属） |
| **新手引导任务** | 自动完成「开始使用 Rewards」里的可自动项（浏览赚取页、了解级别等） |
| **自动领取积分** | 自动领取「可领取」积分，并用积分变化双重校验 |
| **移动应用签到检测** | 每次运行检测该任务状态并明确提示（详见下文说明） |
| **本地网页控制台** | 总览 / 账号管理 / 设置 / 历史 / 实时日志 |
| **系统托盘常驻** | 托盘右键：打开控制台、立即执行、暂停定时、退出 |
| **开机自启** | 注册到启动项，开机静默后台启动 |
| **浏览器可选** | Edge（默认）/ Chrome / Playwright Chromium |

## 快速开始

### 1. 环境要求

- Windows 10 / 11
- [Node.js](https://nodejs.org/) 18 或更高（本项目在 Node 24 上实测通过）
- 已安装 Microsoft Edge（默认使用；也可用 Chrome）
- 已加入 Microsoft Rewards 的微软账号（可多个）

### 2. 安装依赖

```bat
npm install
```

### 3. 启动软件

双击 **`启动.bat`**，会自动打开控制台 <http://127.0.0.1:8787>。

首次启动时软件已为你建好一个「主账号」。接下来：

1. 打开控制台的 **账号管理** 页；
2. 对某个账号点 **登录**，在弹出的浏览器窗口中登录对应的 Microsoft 账号（完成密码 + 验证码/手机验证，只需一次）；
3. 需要多个账号时，点 **+ 添加账号**，再对新账号点 **登录**。

**登录态保存在每个账号各自的 `data/accounts/<账号id>/browser-profile/`，互不影响。**

> ⚠️ **登录多个账号时请注意顺序**：登录完账号一后，若浏览器还保留着它的微软会话，
> 直接去登录账号二很容易被自动带进账号一。建议每个账号登录前先点一次
> **「重置登录」**（只清该账号自己的会话），登录后确认页面上显示的是本账号。

### 4. 设置执行时间

进入 **设置** 页 → 定时执行 → 添加执行时刻（默认 `09:10`）。多账号会在该时刻依次错峰执行。

> 页面顶部的「仅当前账号 / 全局默认」下拉框决定保存范围：
> 定时、托盘为**全局**设置；搜索、任务、浏览器可按**账号**单独配置。

## 任务覆盖范围：会自动做什么、什么要人工

每次运行会**采集仪表盘上的全部任务**（不止每日活动），逐项处理并明确报告结果。

### 自动完成

| 任务来源 | 例子 | 说明 |
| --- | --- | --- |
| 每日活动 | 我附近即将举行的活动 +10 等 3 项 | **点击卡片**执行 |
| 新手引导 | 完成每日任务集 +50、浏览赚取页面 +10、了解您的级别 +10 | 访问对应页面 |
| 积分赚取页 | 页面上的活动/测验 | 视情况尝试 |
| 可领取积分 | 「可领取 N 领取」 | 自动领取并校验 |

### 需要你人工完成

| 任务 | 原因 |
| --- | --- |
| **设定奖励目标 +50** | 要在积分商城里挑选一个礼品卡并确认，属于个人选择 |
| **移动应用签到** | 只能在手机必应 App 内签到（见下节） |

这两项每次都会在日志和「任务清单」里**明确列出**，不会假装完成。

> 重要实现细节：每日活动的任务卡是 `target="_blank"` 的链接，**必须点击卡片**
> （在新标签页中打开）才会被记入积分归属；用程序直接跳转到同一个 URL 是**不记分**的。
> 这一条是实测出来的：直接跳转积分不变，点击卡片后 3 项任务 +80 分全部到账。

## 移动应用签到：为什么不能自动完成

「移动应用 签到: 0/1」这项任务（约 5 分）**只能在手机上的「必应」App 内签到**才会被记录。

实测确认：

- 用移动端 UA 模拟访问 Rewards 页面，该任务只渲染出一张**状态卡片**，没有任何可点击动作、也没有链接；
- 页面内不存在任何可触发签到的端点，唯一相关链接是 App 下载地址 `https://bingapp.microsoft.com/bing`；
- 该任务的进度由 App 端上报，网页端无法构造。

所以本工具的做法是**如实检测 + 明确提示**，不会假装完成：

```
[5/6] 检查「移动应用签到」…
[WARN] 移动应用签到：未完成（0/1）—— 必须在手机必应 App 内签到，网页端无法自动完成。
[INFO]   下载/打开入口：https://bingapp.microsoft.com/bing
```

检测结果会记入历史记录。如果不需要该提示，可在 **设置 → 任务设置** 中关闭「检测移动应用签到」。

其余任务（自动搜索、每日活动、领取积分）均已自动化——移动应用签到是**唯一**需要你手动补一下的项目。

## 日常使用

### 控制台页面

| 页面 | 内容 |
| --- | --- |
| **总览** | 当前账号的积分、今日获得、下次执行、执行状态、今日额度、全部账号概览、最近执行 |
| **账号管理** | 添加 / 登录 / 执行 / 刷新 / 改名 / 停用 / 删除账号 |
| **设置** | 定时、搜索、任务、浏览器、托盘；可按账号或全局保存 |
| **历史记录** | 各账号每次执行的时间、搜索次数、积分变化；可切「显示全部账号」 |
| **运行日志** | 实时日志（SSE 推送），行内带账号标识 |

顶部操作：**本账号执行** / **全部账号执行** / **停止** / **登录本账号** / **刷新账户**。

### 「自动刷满」的判定

Rewards 不公开「今日还剩多少次搜索」，因此采用行为判定：每次搜索后重读页头积分，**连续 3 次**（可配置）不增长即判定刷满并停止；另有 `单次最大搜索次数`（默认 40）作为安全上限。

### 命令行方式

```bat
node app/main.js                        启动控制台（默认）
node app/main.js --once                 立即执行一次（默认第一个启用账号）
node app/main.js --once --all           依次执行全部启用账号
node app/main.js --once --account=acc-2 只执行指定账号
node app/main.js --login                引导登录（可配 --account=）
node app/main.js --add-account 小号A     新增账号
node app/main.js --list-accounts        列出所有账号及状态
node app/main.js --tray                 仅后台托盘常驻
node app/main.js --install-tray         注册开机自启
node app/main.js --uninstall-tray       取消开机自启
node app/main.js --status               打印状态（JSON）
```

### 三个快捷方式

| 文件 | 作用 |
| --- | --- |
| `启动.bat` | 启动控制台 + 调度器 + 托盘（正常使用这个） |
| `登录账号.bat` | 打开浏览器引导登录（默认第一个启用账号） |
| `立即执行一次.bat` | 不开界面，立刻跑一次后退出 |

## 配置说明

所有设置都可以在**控制台 → 设置**页修改，保存到 `data/settings.json`。

### 定时执行（全局）

| 项 | 说明 |
| --- | --- |
| 调度模式 | `每天固定时刻` / `每隔一段时间` |
| 执行时刻 | 支持多个，例如 `09:10` 与 `20:30` |
| 每账号每天最多执行 | 防止重复刷取；手动执行不占额度 |
| 账号间错峰间隔 | 默认 90 秒，多账号依次启动 |
| 错过时刻自动补跑 | 到点时软件没开，之后再打开会补跑（宽限 12 小时） |
| 软件启动后立即补跑一次 | 每次打开软件就跑一次 |

### 搜索设置（可按账号）

| 项 | 说明 |
| --- | --- |
| 自动刷满 | 按「积分不再增长」自动停止（推荐开启） |
| 移动端模式 | 用手机 UA + 移动视口搜索，覆盖移动端搜索额度 |
| 单次最大搜索次数 | 安全上限，默认 40 |
| 搜索间隔（秒） | 默认 3–7 秒随机 |
| 连续未涨分则停止 | 默认 3 次 |
| 搜索词来源 | 混合内置词库 / 必应热榜 / 自定义词库 |

**自定义词库**：`data/accounts/<账号id>/queries.txt`，每行一个关键词。

### 任务设置（可按账号）

启用任务处理、完成每日活动、自动领取积分、刷新赚取页、检测移动应用签到、尝试每日测验（实验性）。

### 浏览器（可按账号）

Edge / Chrome / Playwright Chromium；「后台无窗口运行」默认开启（静默执行）。

## 常见问题

**Q：双击 `启动.bat` 窗口一闪就没了？**
已修复。原因是 `.bat` 若以 UTF-8 保存，中文 Windows 的 cmd 会按 GBK 解码导致命令被拆断。现在所有 `.bat` 都是**纯 ASCII 内容**。

> 若要自己改 `.bat`，请**只用英文/ASCII**（中文提示由 Node 输出）。必须写中文时，请用记事本「另存为」选 **ANSI**。

**Q：怎么添加第二个账号？**
控制台 → 账号管理 → 「+ 添加账号」，然后对新账号点「登录」。建议先点「重置登录」再登录，避免被浏览器里上一个账号的会话带跑。

**Q：明明点了账号二的执行，实际却按账号一在跑？**
这是**必应会话与 Rewards 账号不一致**导致的（同一配置目录里，必应页头还停在另一个账号上）。
本工具已做两件事：
1. 积分与额度判定**一律以 Rewards 页面为准**，不再采信必应页头，避免按错账号判断；
2. 检测到不一致时会在日志和账号卡片上**明确告警**。

彻底修复方法：对该账号点 **「重置登录」**（只清它自己的会话），然后重新「登录」，并确认必应首页页头显示的是本账号。

**Q：多个账号会同时打开浏览器吗？**
不会。调度器一轮只执行一个账号，同时到点的多个账号按「账号间错峰间隔」依次启动。

**Q：某个账号未登录会怎样？**
该账号的执行会失败并提示登录，**不影响其他账号**。

**Q：为什么「今日自动执行」是 0？**
该计数只统计定时/启动补跑，手动执行不计入；每日上限判断也是如此。

**Q：托盘图标没出现？**
本机若只有 Windows PowerShell 5.1（无 PowerShell 7）也能正常工作。可在设置里关掉再开启一次重试。

**Q：软件关了还会执行吗？**
不会。需要保持 `启动.bat` 的进程运行（可关闭控制台网页，但别关掉托盘程序）。开启「开机自动启动」后开机即自动常驻。

**Q：设置改了就自动变回去？**
已修复。原因是状态轮询每 5 秒重填一次设置表单，把你在输入框里刚改的值覆盖掉了。
现在只要你在设置页动过任何一项，就会**暂停自动重填**并显示「你有未保存的修改」提示；
改完点「保存设置」（或按 **Ctrl+S**）即可，不想保存就点提示条里的「放弃修改」。

**Q：某次执行失败怎么排查？**
看「运行日志」页，并按时间查看 `data/logs/YYYY-MM-DD.log`；若开启「失败时保存截图」，可在 `data/accounts/<账号id>/screenshots/` 看到当时的页面。

**Q：总览页「任务清单」显示「待人工」是什么意思？**
表示该项工具无法自动完成，需要你手动处理——目前只有「设定奖励目标 +50」和「移动应用签到」两项。清单里会附带入口链接。

**Q：为什么积分增长显示 +0，但任务确实做了？**
每日活动/新手任务的积分入账有延迟（实测数分钟到数小时），且它们和搜索积分是不同类目。工具以「Rewards 仪表盘上的积分 + 任务完成状态」共同判断，执行结束后会再复核一次并告诉你「还剩几项未完成」。

## 实现要点

- **任务采集要抓全，不能只看 `#dailyset`**：「开始使用 Rewards」区块**没有 id**，靠标题文本定位；它的任务是普通 `<a href>` 而不是搜索链接。早期只解析 `#dailyset`，导致新手任务被整体漏掉。
- **卡片文本要用 `textContent` 兜底**：React Aria 的 `DisclosurePanel` 里存在隐藏测量层，这些节点的 `innerText` 会返回空字符串，只能靠逐节点拼接的 `textContent` 拿到内容。
- **每日活动必须「点击卡片」**：卡片是 `target="_blank"`，点击后在新标签页打开才计分；直接 `goto` 同一 URL 不计分（实测：goto 积分 +0，点击卡片 +80）。
- **账号权威数据源是 Rewards，不是必应页头**：实测同一个浏览器配置里必应页头的会话可能停在另一个账号上（`#id_rh_w` 显示别人的积分与昵称），只看页头会按错账号判断额度。积分、登录判定、额度计算全部以 Rewards 页面为准；页头仅在同一次运行内做相对变化参考，并每 5 次搜索用仪表盘校准一次。
- **会话错配检测**：比较必应页头与 Rewards 积分，采用「绝对差 > 15 分 且 相对差 > 20%」双阈值判定（避免入账延迟造成的误报），命中即告警并切换到 Rewards 判定。
- **浏览器上下文按账号隔离**：`Map<accountId, context>`，每个账号一个独立 `user-data-dir`。早期实现只保存单个活动上下文，会让第二个账号复用第一个账号的配置目录。
- **重置登录**：走真实注销端点 + 清空该账号全部 Cookie + 验证确实登出（SSO 的 `ESTSAUTH` 残留会导致自动回落到上一个账号）。
- **移动端搜索**：通过 CDP `Emulation.setUserAgentOverride` + `setDeviceMetricsOverride` 在页面级切换，无需第二套配置目录。
- **拟人化**：随机间隔、逐字输入、随机滚动、热榜话题混入关键词；点击选项时排除「跳至内容」等无障碍跳转链接。

## 使用须知

本工具通过浏览器自动化代替你手动点击搜索，属于第三方非官方工具，**与 Microsoft 官方无关**。请注意：

- Microsoft Rewards 的服务条款不鼓励自动化脚本，**过度或异常使用可能导致积分不予发放、账号受限**。请自行评估风险，保持合理的搜索次数与节奏。
- 多账号操作会进一步放大上述风险，请谨慎使用，且仅限你本人拥有的账号。
- 程序不含任何破解或绕过登录的逻辑：登录、验证码均由你本人在真实浏览器中完成。
- 使用本工具产生的一切后果由使用者自行承担。
